# Patient Service Manager

A RESTful backend service for managing patient information, built with **Spring Boot**, **Spring Data JPA**, and **PostgreSQL**.

The project provides CRUD APIs for patients and uses a layered architecture with Controller, Service, Repository, Entity, DTO, and Mapper layers.

> **Status:** Development project

---

## 1. Features

- Create a patient
- Get a patient by ID
- Get all patients
- Update patient information
- Delete a patient
- PostgreSQL persistence through Spring Data JPA
- UUID generation for patient IDs
- DTO-based request/response handling
- MapStruct for entity/DTO mapping
- Environment-based database configuration through `.env`
- Centralized API response structure
- Custom exception for patient-not-found cases

## 4. Architecture

The application follows a simple layered architecture:

```text
Client
   │
   ▼
PatientController
   │
   ▼
PatientService
   │
   ├──────────────► PatientMapper
   │
   ▼
PatientRepository
   │
   ▼
PostgreSQL
```

### Controller

`PatientController` exposes the REST endpoints under:

```text
/api/patients
```

It receives HTTP requests and delegates business operations to `PatientService`.

### Service

`PatientService` contains the application logic for:

- Creating patients
- Updating patients
- Finding patients
- Listing patients
- Deleting patients

### Repository

`PatientRepository` extends:

```java
JpaRepository<Patient, String>
```

which provides standard CRUD operations.

### Mapper

MapStruct is used to convert between:

```text
PatientRequest
       ↓
    Patient
       ↓
PatientResponse
```

### Entity

`Patient` is mapped to the PostgreSQL table:

```text
patient
```

The ID is automatically generated as a UUID.

## 5. Patient Data Model

A patient contains:

| Field | Type | Description |
|---|---|---|
| `id` | String | UUID generated by the application |
| `fullName` | String | Patient full name |
| `dateOfBirth` | LocalDate | Date of birth |
| `gender` | String | Gender |
| `phone` | Long | Phone number |
| `address` | String | Address |

# 8. Database Configuration

The application uses PostgreSQL.

The configuration is read from environment variables:

```yaml
spring:
  datasource:
    url: ${URL_DB}
    username: ${USERNAME_DB}
    password: ${PASSWORD_DB}
```

Create a `.env` file in the project root:

```env
URL_DB=jdbc:postgresql://localhost:5432/patient_db
USERNAME_DB=postgres
PASSWORD_DB=your_password
```

Example PostgreSQL database:

```sql
CREATE DATABASE patient_db;
```

> Do not commit `.env` or database passwords to Git.

# 12. Data Encoding Note

The project currently contains an `EncryptConvertor` that uses Java Base64:

```java
Base64.getEncoder().encodeToString(...)
```

and:

```java
Base64.getDecoder().decode(...)
```

This provides **encoding**, not cryptographic encryption.

Base64 does not protect sensitive patient information from someone who can access the database.

For a production healthcare application, sensitive fields should use a properly designed encryption mechanism with secure key management. Authentication, authorization, auditing, access control, and data protection should also be implemented before handling real patient data.
